# Run the Harness

Each owner follows the layer pipeline in `AGENTS.md` and the applicable `$novel` phase document. A later discovery fixes the earliest owning layer and propagates through every dependant.

Begin each package with the work-specific contract pass. Before bulk settings authorship, the coordinator confirms that every direct directive has one canonical owner, each adopted package target is active in an additive claim with the owning layer's stage and review behavior, and an empty `claims` array reflects a literal audit rather than omission.

Follow `$evidence-graph` [staging](../evidence-graph/staging.md) as one package-wide transaction for each layer. After the owner completes its review step, require the coordinator's independent clean package build, complete common-obligation audit, and literal quality audit before activating the next layer.

The exclusive package owner decides when its complete layer satisfies the staging prerequisites and changes that layer from `disabled` to `evidence`, then from a clean committed evidence state to `review`. The coordinator does not pre-authorize, schedule, or micromanage those transitions. It verifies that the declared state is the state actually passed to the shared factory, observes the active-stage behavior, and retains the independent post-review gate before the next layer.

Calibrate observation, draft autonomy, evidence repair, and strong intervention by [Stage-Calibrated Supervision](observe.md#stage-calibrated-supervision). In particular, a complete `disabled` first version precedes the diagnostic evidence pass; intermediate evidence errors are repaired rather than hidden or treated as a completed gate.

After each coherent creation or material revision of one authored document, its owner stages exactly that one owned path, passes staged `git diff --check`, verifies that the cached name list contains only that path, then commits and pushes it with a document-specific message. Run the scoped package build at the [verification scope](../evidence-graph/staging.md#verification-scope) owned by the active phase and whenever an evidence diagnostic or package change requires it. A state-transition commit follows only the complete coherent snapshot required by staging. Never create an empty or partial commit, broad-stage, mix coordinator or foreign-package files, change part of a layer to the next state, start review with unresolved evidence diagnostics, or begin a downstream layer while the required build fails.

Serialize shared-checkout Git mutations with one atomically acquired `.git/codex-benchmark-commit.lock`. While holding it, require an empty pre-existing staged index before staging the exact owned path; release it on success or failure. Unstaged changes in another owner's package are not a reason to stop and must remain untouched. A staged-diff error, unexpected cached path, commit failure, or push failure is a hard stop to report, never a condition to ignore or work around. An observed nonzero build forbids a gate claim and unrelated progression; during an active `evidence` repair it permits only work that resolves that diagnostic population and honest current-state checkpoints until the build is clean. A progress commit records work in the current state; it does not certify a partial layer as complete. The coordinator commits shared, cross-package, manifest, README, and instruction changes separately.

Use the hierarchy and common-unit topology in `AGENTS.md`. Any scope reduction follows `config/docs/obligations/common.md#scope-preservation`; speed is not approval.

When a real work-specific evidence need emerges during authorship, stop the affected batch and rerun `$novel` [Work-Specific Contract](../novel/work-specific.md). Resume only after its authority, owner, target, and activation are settled. Record the resulting target family, populations, cardinality, exclusions, stage, and review behavior in coordinator status, and validate them at the next required package gate. Do not create an empty target or edit the shared harness from a package owner.

Before authorizing scenarios, the coordinator and owner must literally read the full storyline and confirm that its H4s already show reader orientation, the work's chosen connection and cumulative development, changed relationships, information, or formal effects, legible bridges across every deliberate cut, and a scale consistent with the declared work. Where agency and conflict operate, also require consequential choices, attempts, and responses. Before authorizing manuscripts, confirm that the scenario can be staged without inventing its essential positions, actions or processes, applicable decisive exchanges, or exit conditions. Structural and body-size measures detect regression; these literal checks decide whether the material is actually sufficient.

Maintain a local coordinator status record under ignored `.wiki/benchmarks` so another agent can resume without turning operational notes into novel evidence. Never stage, commit, or push `.wiki`. Track each package owner, current phase and unit, lint states, configured extra claims and target families, package build, next actions, major decisions, unresolved research, and uncollected setups.
