# Design the Run

Read `AGENTS.md`, the root `README.md`, shared config and principles, and every selected package manifest and lint state before launch.

- Treat one package as one experimental unit. Choose deliberately different genres, research burdens, voices, structures, and audiences.
- Fix the common harness before authorship: skills, universal principles and obligations, graph factory, layer order, stage semantics, compiler gates, output language, review completion, and any scale target. Explicitly define the layer contract: detailed narrative treatment in storylines, production-capable initial script in scenarios, and finished literary prose in manuscripts.
- Design each package's initial extra graph independently. Keep the explicit `claims` array empty when the work has no extra contract; otherwise append typed claims only in that package's `lint.config.ts`. Classify each independent target as a package principle, obligation, or descriptive third family, and follow `$evidence-graph` for its directory, filename, anchors, and activation. Declare the target family, host and reference populations, cardinality, exclusion behavior, stage, and review rule in the benchmark brief. A benchmark may test genre conventions, research duties, formal constraints, or additional cross-layer relationships without pretending they bind every novel.
- Do not promote a successful package rule into `config/docs/principles` during the run. Record it in `.wiki`, compare counterexamples across works, and promote it only when it survives the shared instruction contract's universality test.
- Announce the lineup before launch. Keep the root README table current with package link, title, subject, genre, experiment axis, and honest status.
- Create new units only with `pnpm create:novel`. Run install and root `build` before agents start. Scaffolding creates structure, not story content.
- Define observations beforehand: elapsed transitions, diagnostics repaired, upstream revisions, stale reviews renewed, literary findings, and clean review rounds. Without a designed control, call the result exploratory rather than causal proof.
