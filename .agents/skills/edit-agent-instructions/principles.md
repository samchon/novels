# Principles

Principles live in `config/docs/principles` as `common.md`, answered by every authored file; `narratives.md`, answered by the three narrative layers; and one file per authored layer. The evidence graph compiles each file as a checklist, so every edit changes what every host file must answer.

## Shape

Give each file exactly one H1, non-evidence overview prose above the first H2, and one anchored H2 per principle. Add no deeper heading.

Give every item a stable `{#anchor}`; hosts cite `principles/<file>.md#anchor`.

Close each item with a `Sources:` line of externally checkable references. An item no source supports is a preference the compiler cannot arbitrate.

## Content

Keep every item independent of any work's subject, genre, characters, setting, and ending.

Ask one question per item. Two items that ask the same question do not double the check: the second answer copies the first, and the file is examined from one fewer angle than its count claims.

Name the boundary when a neighbouring item owns an adjacent concern, so an answer cannot drift into it.

State an item's limit as a condition inside the item, never as grounds for exclusion. No principle item may be excluded, so an item that cannot bind everywhere must name what triggers it — and must not borrow the exclusion tag's wording to do so.

## Consequence

Editing an item expires every file's answer to that item in every package. Before changing wording, weigh the change against the reviews it invalidates; afterwards renew those answers by rereading the item against each host, never by refreshing the fingerprint alone.

Adding an item obliges every host file in its layers to answer it. Placing a rule in `common.md` or `narratives.md` therefore costs more than placing it in one layer's file; choose the narrowest file that owns the concern.
